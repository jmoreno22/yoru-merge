## Findings — stage 1 (block ship)

Each finding: where · AC · problem · resolution (owner decision of 2026-09-03 via AskUserQuestion).

- **F-1 Escape wipes an in-progress commit message.** `src/app/core/services/escape-layers.service.ts:86,109` with `src/app/features/working-changes/commit-composer.html:89`; AC-15, AC-10. The built-in rank-4 rule clears *any* focused input / textarea with content; the composer's subject and body had no Esc handler before this branch, so one Esc destroys an unsent draft — contradicting the feature's own «a draft must survive a trip through the diff workspace». → **Fix now → T17.**
- **F-2 No 75 % floor for the collapsed header; the test cannot fail.** `src/app/core/services/inspector-layout.ts:30,66-74`; `inspector-layout.spec.ts:116-145`; AC-02. Only `DIFF_SHARE_FLOOR = 0.5` exists; with the header collapsed and ≥ 4 drawn rows at comfortable density the diff is under three quarters (≈ 63 % with 6 rows at 700 px). Both 75 % tests pass `fileCount: 2`, the one region where the 0.5 floor yields 81 %. Also misses T1's own DoD. → **Fix now → T16.**
- **F-3 Three of the six shortcuts never reach Settings › Keyboard.** `src/app/features/diff-workspace/diff-workspace.ts:86-113` with `src/app/features/settings/settings-dialog.ts:396`; AC-12. `diff-workspace.close` / `.next` / `.prev` are registered by a component alive only while the workspace is open; the Keyboard table renders live registrations, so with the workspace closed neither Close nor file navigation is listed. The two inspector toggles vanish the same way in the Changes view. `screens.md` SCR-05 declares all six rows as the default state. → **Fix now → T18.**
- **F-4 A watcher event never reloads the diff shown in the workspace.** `src/app/core/services/ops/repo-ops.ts:124,201`; AC-16. `runRefresh` never calls `refreshActiveDiff`, whose only callers are the app's own staging operations; an external edit leaves stale patch text, and the §6.1 abuse case «staging a stale hunk after the file changed on disk» is unmet. → **Fix now → T19.**
- **F-5 An external change that empties the shown file advances instead of closing; own-vs-external is a one-second clock.** `src/app/core/services/diff-workspace-state.ts:105`; `src/app/features/working-changes/working-changes.ts:61,266`; AC-13, AC-16. `setFiles` returns `advance` whenever other files remain, so the AC-16 notice at `working-changes.ts:268` is reachable only when the whole side empties; `OWN_ACTION_WINDOW_MS` is the only thing choosing between the AC-13 and AC-16 notices, and its premise about the watcher (`workspace.store.ts:276` suppresses relative to the last *refresh*, not the last staging call) does not hold. The `advance` branch also never sets `navigated`, so a later close focuses a vanished row. → **Fix now → T19.**
- **F-6 Focus restore is incomplete on three counts.** `src/app/core/services/diff-workspace.service.ts:40-49,202`; `src/app/features/commit-list/commit-list.ts:213`; `commit-list.html:61`; `commit-inspector.ts:286,677`; `diff-workspace-state.spec.ts:27,42`; AC-08. (a) `focusRow` does one `querySelector` and returns when the row is absent — both restore targets live in CDK virtual viewports, and the owner resolved on 2026-09-03 (test-plan §Open questions) that the row must be scrolled into view first; (b) the restore is queued with `afterNextRender` before the remounted commit list queues its `scrollToOffset`, so the row is not yet in the DOM; (c) the AC's second branch — focus on the commit row when opened by shortcut from the centre — does not exist: the only opener always passes the file path, so `data-focus-key="row.sha"` is inert; the unit fixtures use key shapes (`commit-row:abc123`) the app never produces. → **Fix now → T20.**
- **F-7 AC-07 and AC-17 collide and the code decides; the stale diff stays.** `src/app/core/services/diff-workspace.service.ts:112`; `commit-inspector.ts:292-300`; `diff-workspace-state.ts:98-101`; AC-07, AC-17. The close-on-change effect closes the workspace as soon as `selectedCommitSha` moves, while AC-07 required a workspace whose commit a refresh removed to stay open on the viewer's explanation; in the residual case (sha stays, details no longer match) nothing clears `diffText`, so the centre keeps the diff of a commit that no longer exists. Known gap from the implement stage. → **Owner decision: AC-17 wins.** Spec AC-07 amended in place (marker `amended-by-review 2026-09-03`): a refresh that removes the shown commit is a selection change and follows AC-17; only the binary case and the residual «sha stays, list empties» case show the viewer's explanation. The residual path still needs the stale diff cleared. → **Fix now → T21.**
- **F-8 The layout policy is fed an uncapped header height while the CSS cap silently stopped applying.** `src/app/features/commit-inspector/commit-inspector.ts:525` against `commit-inspector.css:6` and `src/app/shared/components/main-content/main-content.html:110`; AC-01, AC-03. `headerFixedH` comes from `scrollHeight`, which ignores `max-height: 50%`; the wrapper changed from `flex-[2]` to `flex-none`, so the percentage resolves against a content-sized parent and computes to `none`. The comment in the code describes a cap that no longer exists. → **Fix now → T22.**
- **F-9 The component test tier the plan mandates was never enabled.** `docs/features/inspector-diff-workspace/test-plan.md:25,139` vs `tasks.json`; `vitest.config.ts:1-22`; `AGENTS.md` §TESTING; AC-01, 02, 04, 05, 06, 07, 08, 09, 10, 11, 12, 13, 14, 15, 16, 17, 18, 21. The plan marks the component tier `Yes` (owner decision 2026-09-03) and requires a tooling task before T7 / T9; `tasks.json` has none, the runner is still `node`-only, and the branch adds only four pure-TS specs. 18 of 21 ACs have no UI-level assertion; AC-14, AC-15, AC-18 and AC-21 have zero automated coverage of any kind. → **Owner decision: honour the plan.** → **Fix now → T15 (tooling), T24 + T25 (component rows).**
