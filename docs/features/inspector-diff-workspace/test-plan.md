# Test plan — inspector-diff-workspace

> **Glossary:** [feature CONTEXT](./CONTEXT.md) · [project CONTEXT](../../../CONTEXT.md)
> **Upstream:** [spec.md](./spec.md) §5 AC-01…22, §6 NFR · [sad.md](./sad.md) §5 ownership rules, §6 flows, §10 quality goals, §11 accepted debt · [ux-flows.md](./ux-flows.md) (the e2e-through-UI scripts) · [screens.md](./screens.md) (the states every component row must cover) · [tasks.json](./tasks.json) (the `Task` column) · ADR-0001…0004.

The inspector must protect the commit file list's height (the body clamp yields first, then the expanded header scrolls inside its cap, floors at one clamp line and two rows), and any single file's diff must open at full centre width and close back to the exact previous selection, scroll and focus, in both History and Changes, with Esc closing only the topmost of six layers.

## Edge cases / error paths

- **Binary file without preview opened in the workspace (AC-07)** → expected: the diff viewer's existing plain explanation in the centre, strip and navigation active, Close returns normally.
- **Commit removed by a refresh while the workspace is open (AC-07, amended 2026-09-03)** → expected: when the refresh moves the selection the workspace closes via AC-17 and the History view shows the new selection; when the commit stays selected but its list empties, the diff text clears, the explanation shows, previous / next are disabled and Close returns normally.
- **Diff load fails for the shown file (not binary, an error from the bridge)** → expected: the existing failure toast (SAD §8), the workspace stays open with the previous content, nothing half-rendered.
- **Staging from a commit-sourced workspace by control or shortcut (AC-14)** → expected: no control exists, the shortcut does nothing, no bridge call.
- **Commit or commit-draft shortcut while the working-tree workspace is open (AC-15)** → expected: nothing committed, no bridge call.
- **External change empties the shown side (AC-16)** → expected: the workspace closes, the Changes view returns, the «changed outside the app» notice shows without taking focus.
- **Own stage action on stale content after the file changed on disk (spec §6.1)** → expected: today's failure toast, nothing half-applied, the workspace refreshes to the real content.
- **Commit with exactly one file** → expected: both previous and next disabled; open, close and focus restore still work.
- **File list in tree order with folder rows** → expected: the published order contains only files; previous / next never land on a folder.
- **Available height below the floors (the list's share does not fit what is left)** → expected: the policy holds rows = 2 and clamp = 1, never negative, and lifts the header cap to one panel head rather than letting it disappear behind its own scrollbar — the bottom placement's 220 px minimum with blame and file history stacked (`inspector-layout.spec.ts`, `binds both hard floors…`, T40). <!-- re-pointed 2026-09-08 (T46, review round 10 R10-S1-F5): the expectation named a diff the History column no longer has, and `sad.md` §11's row is about the stacked-panel remainder -->
- **Non-boolean value for either collapsed preference in the stored file** → expected: the normaliser falls back to false, the app starts expanded.
- **Esc with only a tooltip or a hover state showing** → expected: none of the six layers is open, so the workspace closes.
- **A layer consumer that forgets to unregister on close** → expected: caught by the component rows of AC-10 — a phantom layer would make the workspace ignore Esc; registration is tied to the component's destroy hook.
- **Originating row scrolled out of the virtual-scroll viewport at close time** → expected: the file list scrolls the row into view, then focuses it (owner decision 2026-09-03); the commit-list scroll offset from the snapshot is not affected.
- **Repository tab closed while the workspace is open** → expected: closes as a tab change (AC-17), no snapshot replay.
- **Workspace open and the app is closed / relaunched** → expected: the workspace never persists; the app starts on the normal centre view (ADR-0001, feature CONTEXT invariant).

> **No live artefact writes a figure derived from the code** (owner decision **D3**, 2026-09-10,
> review round 17). A number produced by `computeMetrics` or by the layout policy — a token, a cap, a
> share, a band bound, a configuration count — may not be written into prose in `spec.md`, `sad.md`,
> `ux-flows.md`, `screens.md`, this file, `DESIGN.md`, `ARCHITECTURE.md` or `adr/`. Write the **closed
> form** in `panelHeadH` / `fileRowH` instead. Concrete reference figures live in exactly one place:
> the generated reference table (`reference-figures.md`, T70), regenerated from the shipped modules
> by `pnpm figures:write` and byte-compared by `pnpm check:figures`, so a stale copy fails the gate. A test's own assertion is the figure's home and may carry it; a *comment*
> beside that assertion may not restate it.
>
> *Why this rule and not more vigilance.* Nine consecutive review rounds found «a precise figure that
> is false» — and rounds 16 and 17 found it **inside the two instruments built to prevent it**: the
> closed form written so figures could not go stale was itself wrong by a pair of parentheses
> (R17-F1), and the coverage claim of the gate written to catch stale figures counted values against
> lines (R17-F8). A number that is never written cannot go stale; a number that is written is a
> number someone must re-derive on every wave, and nine waves running, someone did not.
>
> **A sweep's scope is the branch, not a list** (owner decision **D4**, 2026-09-10, review round 17).
> Any sweep — a grep for retired wording, a figure check, a carrier enumeration — is scoped to **every
> tracked file the branch touches** (`git diff --name-only <base>..HEAD`, plus the working tree and
> untracked files). Exclusions are allowed and must be **named with their reason** in the same place
> the sweep is reported; ADRs and task records are in scope by default. A sweep that declares a
> narrower scope than the one it executed fails mechanically (T70).
>
> *Why.* After R15-S1-F3 the owner already replaced enumerated file lists with this rule. Round 16's
> wave declared it and still missed `adr/0003` (R17-F4), and the mechanical successor built in the
> same wave was given an enumerated eight-file list. Declaring a scope and executing a smaller one is
> the failure; the check exists so the two cannot diverge silently.

> **When a row quotes a configuration count.** Two loops in `inspector-layout.spec.ts` sweep the same
> table, and a row must quote the loop's **arithmetic**, never a literal. The **share** sweep (the one
> AC-01 and AC-02 cite) is `DENSITIES.length × heights.length × fileCounts.length × 2`: it fixes
> `fileListCollapsed: false`, because a collapsed list claims no share by design. The **whole-pixel
> cap** row above it iterates that flag too, so it is that product × 2. Within the share sweep the
> `DENSITIES.length × heights.length × 2` `0`-file configurations assert the bare head, and their
> invariant does not depend on `headerCollapsed`, so half of them are duplicates — breadth is rows of
> assertion, not distinct behaviours (review round 11 O9). **The three products, read out of the loops themselves, are in [`reference-figures.md`](./reference-figures.md) §Sweep configuration counts.**

> Restated as arithmetic 2026-09-10 (T63, review round 16 R16-S1-F3): the literals were 192 / 384 / 32,

- **Seed strategy (unit).** Table fixtures, no files on disk: density token sets **derived from `computeMetrics`** rather than hard-coded, so a fixture cannot describe a configuration the app has no way to produce (the `--panel-head-h` / `--file-row-h` pair each density yields is in [`reference-figures.md`](./reference-figures.md) §Density tokens); file lists of 0, 1, 2, 6, 7 and 30 paths, once in flat order and once as the visible tree order with folders removed; snapshots `{ selectedCommitSha | side, activeFile, listScrollTop, focusKey }`; the 64 subsets of the six Esc ranks; raw preference objects with booleans and with non-boolean noise.
- **Seed strategy (component).** Fixture commits built in memory: a subject-only commit with one file; a commit with a 12-line body and 30 files (one of them binary); a commit with two files; a commit with zero files; a working tree with three unstaged and two staged files. - **Seed strategy (manual e2e-through-UI).** A throwaway Git repository created by a script before the checklist run and deleted after: a 30-file commit with a long body, a two-file commit, an empty commit, a commit touching a binary, a file with a 2 000-line diff, and a working tree with staged and unstaged hunks. - **Cleanup boundary.** Per test in both automated tiers: a fresh fixture and injector per test, the Esc registry reset between tests (a module-level singleton would leak ranks), document-level keydown listeners removed through the destroy hook; no shared mutable globals. The manual repository is per checklist run.
