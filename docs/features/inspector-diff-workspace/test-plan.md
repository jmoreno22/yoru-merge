# Test plan — inspector-diff-workspace

> **Glossary:** [feature CONTEXT](./CONTEXT.md) · [project CONTEXT](../../../CONTEXT.md)
> **Upstream:** [spec.md](./spec.md) §5 AC-01…21, §6 NFR · [sad.md](./sad.md) §5 ownership rules, §6 flows, §10 quality goals, §11 accepted debt · [ux-flows.md](./ux-flows.md) (the e2e-through-UI scripts) · [screens.md](./screens.md) (the states every component row must cover) · [tasks.json](./tasks.json) (the `Task` column) · ADR-0001…0004.

The inspector must hand the diff viewer its height (header and file list yield first, floors at two rows and one clamp line), and any single file's diff must open at full centre width and close back to the exact previous selection, scroll and focus, in both History and Changes, with Esc closing only the topmost of six layers.

## Edge cases / error paths

- **Binary file without preview opened in the workspace (AC-07)** → expected: the diff viewer's existing plain explanation in the centre, strip and navigation active, Close returns normally.
- **Commit removed by a refresh while the workspace is open (AC-07, amended 2026-09-03)** → expected: when the refresh moves the selection the workspace closes via AC-17 and the History view shows the new selection; when the commit stays selected but its list empties, the diff text clears, the explanation shows, previous / next are disabled and Close returns normally.
- **Diff load fails for the shown file (not binary, an error from the bridge)** → expected: the existing failure toast (SAD §8), the workspace stays open with the previous content, nothing half-rendered.
- **Staging from a commit-sourced workspace by control or shortcut (AC-14)** → expected: no control exists, the shortcut does nothing, no bridge call.
- **Commit or commit-draft shortcut while the working-tree workspace is open (AC-15)** → expected: nothing committed, no bridge call.
- **External change empties the shown side (AC-16)** → expected: the workspace closes, the Changes view returns, the «changed outside the app» notice shows without taking focus.
- **Own stage action on stale content after the file changed on disk (spec §6.1)** → expected: today's failure toast, nothing half-applied, the workspace refreshes to the real content.
- **Commit with exactly one file** → expected: both previous and next disabled; open, close and focus restore still work.
- **File list in tree order with folder rows** → expected: the published order contains only files; previous / next never land on a folder.
- **Available height below the floors (both floors plus half the diff do not fit)** → expected: the policy holds rows = 2 and clamp = 1, never negative, and the diff takes the remainder (SAD §11 risk row).
- **Non-boolean value for either collapsed preference in the stored file** → expected: the normaliser falls back to false, the app starts expanded.
- **Esc with only a tooltip or a hover state showing** → expected: none of the six layers is open, so the workspace closes.
- **A layer consumer that forgets to unregister on close** → expected: caught by the component rows of AC-10 — a phantom layer would make the workspace ignore Esc; registration is tied to the component's destroy hook.
- **Originating row scrolled out of the virtual-scroll viewport at close time** → expected: the file list scrolls the row into view, then focuses it (owner decision 2026-09-03); the commit-list scroll offset from the snapshot is not affected.
- **Repository tab closed while the workspace is open** → expected: closes as a tab change (AC-17), no snapshot replay.
- **Workspace open and the app is closed / relaunched** → expected: the workspace never persists; the app starts on the normal centre view (ADR-0001, feature CONTEXT invariant).

## Test data

- **Seed strategy (unit).** Table fixtures, no files on disk: two density token sets (comfortable `--panel-head-h` 34 / `--file-row-h` 30; compact 30 / 30); file lists of 0, 1, 2, 6, 7 and 30 paths, once in flat order and once as the visible tree order with folders removed; snapshots `{ selectedCommitSha | side, activeFile, listScrollTop, focusKey }`; the 64 subsets of the six Esc ranks; raw preference objects with booleans and with non-boolean noise.
- **Seed strategy (component).** Fixture commits built in memory: a subject-only commit with one file; a commit with a 12-line body and 30 files (one of them binary); a commit with two files; a commit with zero files; a working tree with three unstaged and two staged files. The IPC bridge is stubbed at the typed `invoke` wrapper with canned diff text per path and a controllable `repo-changed` emitter; the preferences service is seeded in memory; a `ResizeObserver` stand-in reports the width and height each test needs. No real repository and no backend process in the component tier.
- **Seed strategy (manual e2e-through-UI).** A throwaway Git repository created by a script before the checklist run and deleted after: a 30-file commit with a long body, a two-file commit, an empty commit, a commit touching a binary, a file with a 2 000-line diff, and a working tree with staged and unstaged hunks. The script and the checklist steps live with the release checklist; the same repository is used on Windows and Linux.
- **Integration dependency.** None owned by this feature (see Levels). No datastore is mocked because no datastore is exercised: the store is reached only through the existing preferences service.

The manual repository is per checklist run.

## NFR validation

No NFR in spec §6 carries a rate or concurrency figure, so no load-generation scenario applies (the tool would be the one in the repo, or e.g. k6 / Locust, and none is needed). Every numeric NFR is a single-user measurement, listed here so the release checklist runs each one with its threshold:

- **Diff viewer share, header expanded** → scenario: 4 runs (960 × 640 and 1280 × 800 × both densities), inspector right, no stacked panels; assert element-height share ≥ 50 % in every run.
- **Diff viewer share, header collapsed** → scenario: the same 4 runs with the header collapsed; assert share ≥ 75 %.
- **Diff height at the bottom or with stacked panels** → scenario: 3 runs (bottom; blame stacked; file history stacked) side by side with the 1.0.5 build at 1280 × 800; assert height ≥ the 1.0.5 value in each.
- **Open the workspace from a shown diff** → scenario: 10 repetitions on a 2 000-line diff; assert p95 first paint ≤ 150 ms and exactly 1 diff request per open in the bridge log.
- **Close the workspace** → scenario: 10 repetitions; assert p95 restore ≤ 100 ms with identical scroll offset and selection (the restore logic itself is the AC-08 unit row).
- **Keyboard reachability** → scenario: 1 keyboard-only pass; assert 6 of 6 workspace actions (open, close, previous file, next file, plus hunk previous / next) have a listed shortcut and focus returns to the originating row on close.
- **Esc layer precedence** → scenario: the 64-combination matrix, automated at unit level (AC-10 row) plus the 6-layer manual matrix in the built app; assert 0 mis-fires.
- **Layout regressions in existing modes** → scenario: 8 configurations (2 themes × 2 densities × 2 placements) on Windows and Linux; assert 0 regressions.
- **First paint of the remembered state** → scenario: 2 launches (remembered expanded, remembered collapsed); assert 0 px inspector layout shift between the first painted frame and the settled state.
